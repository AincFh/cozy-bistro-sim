# COZY BISTRO · 日落餐馆

## 新增：熟客回访与长期关系经营

餐厅现在真正记得每一位常来的街坊。**16 位固定顾客分别拥有独立的服务记录、超时流失记录和信任等级**。只有真实到店、消耗食材、成功制作并完成上菜的**普通散客订单**，才会记录一次成功服务；等待超时则扣除 2 点净信任，社区团体订餐不会被错误计入个人熟客关系。

净信任达到 **3 / 8 / 18** 分会晋升熟客 Lv.1 / Lv.2 / Lv.3。等级会真实改变下一营业日的客人选择权重、每级多 **4 秒**的等待耐心和每次上菜额外 **3 金币**的小费；额外收入记入当天收入与小费、并进入历史财务账本。聘用助手正常上菜同样算真实服务，未完成订单、重复上菜和在名册中点击不会增加好感或生成资金。

在**经营账本 → 街角熟客名册**查看每位顾客的成功/失败记录、距离升级所需净信任和当前回访待遇。经营成就另增两项关系目标。已有 `cozy-bistro-save-v1` 存档保持兼容，非法/异常顾客数据在读取时受到校验。新增 11 项 Node 行为回归与完整 Chrome 桌面/手机 UI 验收：真实制作、实际服务、小费结算、存档刷新及名册展示。

## 新增：员工职业成长与培训体系

原来的兼职助手每天只支付固定工资，实际经营时间再长也不会成长。现在小森拥有 5 个技能等级，经验只会在**真实成功的料理制作或上菜**之后每次增加 1 点；失败制作、缺少食材或没有正式聘用都无法获得经验。更高等级使助手操作间隔从 **4.50 秒**逐步下降至 **2.98 秒**。

从营业第 2 天开始，玩家可在「兼职与排班」通过真正的游戏按钮支付培训费用，每天最多培训一次，每次获得 **8 点技能经验**。培训费用从 140 金币起随等级提高。高级助手工资也随等级上涨（起始 98 金币，每级加 12），形成 **效率提升与持续经营成本**之间的取舍。薪资只在确认聘用时扣除一次，培训费用计入当天支出。

员工等级、经验、累计培训次数及费用、当日已培训状态、实际已付工资都保存在原有浏览器存档中；老版存档自动补充缺失字段，不删除食材、升级、订单和营业历史。每天的结算账本记录真实工资和培训支出，新增两项员工成长成就。

- **Node 回归**：技能等级、每日报名约束、真实 XP 与库存消耗、工资支出、历史账本、防止重复训练和旧存档恢复。
- **Chromium 实测**：完整经历第 1 天→第 2 天，实际点击培训与聘用、让助手通过真实厨房引擎工作、等待自动存档、刷新恢复、390px 手机布局以及测试截图。
- **限制**：当前仍是单机游戏中的一个兼职助手职业路径，尚非完整的多人雇员排班、人事招聘或餐馆集团经营系统。

一个离线优先、无需账号的网页餐馆经营模拟游戏。原创游戏机制与视觉设计。**当前状态：可玩经营模拟版本，仍在内容扩充中，不宣称商业级完整作品。**

## 玩法
1. 开业前购买食材或升级厨房。
2. 开门迎客，根据客人的菜单和剩余耐心安排制作。
3. 厨房有并发制作台，升级后可同时处理更多订单。
4. 制作完成后亲自上菜；及时服务可获得小费、经验与口碑。
5. 每日结束查看收益、损耗与客人满意度，再进入下一天。
6. 逐步解锁 8 道菜品、5 类升级以及 7 项成就。历史财务账本记录最近 24 天。

## 新增：每日主推菜 · 经营决策与菜单定价

开业前前往「**餐厅菜单**」选择当天的主推料理，而不只是查看静态菜谱。一次性投入 **38 金币**营销费用，可在开业前自由更换主推（不会重复扣费）。主推菜的散客点单权重为普通菜的 3 倍，零售价上调约 18%；**总体顾客人数不增加**，因此选择原料充足、制作速度合理的菜比盲目选择最贵菜更有价值。

- **可追踪的真实订单**：排队顾客由固定种子决定，挑选主推会直接改变每日顾客菜品分布，厨房仍需要照常消耗原料、制作并及时交付。
- **真实财务风险**：营销费用计入当日支出；仅真正成功上菜的主推菜计入溢价收入、销量和经验；无人购买时不能凭空获得收入。
- **订餐保护**：签约的社区团体仍按约定原价结算，不因当日主推而被加价；同时适配摆盘、小费、兼职助手等既有系统。
- **统计与存档**：保存活动选择、历史已推出活动次数、主推菜销量、每日溢价及最近的财务记录，新增两枚经营成就；可从旧版进度升级。
- **质量门禁**：新增 Node 经济、点单权重、存档和重复支付测试；Chrome 桌面/手机测试通过界面真实完成选菜、付费、开业、制作、上菜、恢复存档，并保存截图。

## 新增：手动摆盘挑战与主厨熟练度

餐厅不再只有「开始制作 → 等待 → 点击上菜」。料理完成后可选择普通上菜，或者启动 **5.5 秒限时精致摆盘**：玩家观察真实移动的标尺，在金色目标区域按空格或点击停止。结果按距离分成完美、良好、合格与未命中，只有成功交付的料理才获得相应金币、额外经验与口碑。

- **失败不凭空生成收入**：超时仅按普通上菜交付；未制作完成的订单无法使用摆盘。
- **真实经济账本**：额外小费计入当日小费与摆盘专项统计；助手代为上菜不会获得玩家摆盘加成。
- **长期成长**：保存累计完美摆盘、最好连胜与已尝试次数，并新增摆盘成就。旧版存档自动兼容。
- **交互和自动测试**：桌面与移动端适配；Node 单测覆盖评分、重复上菜、助手隔离、存档，真实 Chrome 测试通过界面完成一轮计时挑战。

## 新增：智能食材采购

「采购与备货」面板会为每道当前已解锁菜品计算 **3 份料理的食材缺口**，并比较六种配送包的组合，在原有库存基础上选择**总价最低**的可行采购方案。

- 展示具体缺少哪些食材、需要订购哪些配送包，以及完整报价。
- 确认采购前不会扣除金币；资金不足时禁止下单；营业期间禁止补货。
- 确认后一次性完成所有配送包交易，金币、当日支出和多余食材入库一致更新。
- 再次点击已备足的同一道菜不会重复扣费。计算与交易均有独立 Node 单元测试。

## 新增：社区团体订餐

餐馆现在不仅接待散客，还可以在侧栏 **社区订餐** 中查看两份每日变化的邻里委托，选择一份签约。每份合同要求在本营业日完成 2–4 份特定菜品，与散客共享真实的食材库存和厨房制作台。

- **押金与风险**：签约即扣押金；任一订单超时会导致整个委托失败并失去押金和一部分口碑。
- **真实生产**：每份委托仍然要经过顾客到店、厨房备菜、制作完成与上菜；兼职助手可以帮助，但不能无中生有地产生食材和产能。
- **完整交付**：全部成功交付后，押金返还，同时获得额外奖金、经验值与口碑，且每份合同只结算一次。
- **长期进度**：记录累计成功/失败委托与新增成就，合同和待完成订单随本地存档保存，原版旧存档仍可载入。
- **可复现验收**：合同生成由存档种子与经营日期确定，包含经济不变量、重复交付保护、失败结算和中途存档恢复测试。

## 技术
- HTML/CSS/原生 JavaScript，独立引擎 \`src/engine.js\`，不使用外部 CDN、框架或商业素材。
- 进度写入浏览器 localStorage，页面提供手动导出和导入、重新开始。
- 自适应布局。GitHub Actions 在每次 Push/PR 时执行 Node.js 测试；main 部署 GitHub Pages。
- \`npm test\`：引擎及经济闭环测试。
- \`npm run check\`：JS 语法检查。
- \`npm run start\`：本地启动后打开 http://localhost:5173。

## 边界
目前是单机经营模拟游戏而不是 3D 自由探索或多人联机；数据仅留在使用的浏览器和手动导出的备份中。清理浏览器站点数据会删除存档。没有真实支付、用户账号或服务器运营后台。
## 经济保护与离线支持
低资金或无法制作任何已解锁菜品时，每个营业日最多可领取一次免费邻里应急食材。支持状态随本地存档保存。字体使用系统字体，无外部字体请求。

## GitHub Pages 缓存一致性
部署时运行 `npm run build:pages`，用当前提交 SHA 为 HTML 入口、CSS 与应用的全部 ESM 导入（`app.js`→`engine.js` / `scene.js`）添加统一版本标记，产出 `dist/` 静态站点。避免 GitHub Pages 浏览器缓存复用旧 JS 导致新功能看不到或模块版本混搭。CI 对产物执行版本戳检查；本地开发仍运行源码目录。

## 新增：七日街区活动日历
每七天有三场固定可预期的主题活动：**第 3 天小集市**（额外 2 位散客，清爽饮品/轻食偏好提高、耐心 -3 秒）、**第 5 天咖啡节**（额外 3 位散客，饮品偏好提高、耐心 -5 秒）、**第 7 天家庭日**（额外 3 位散客，早餐/甜点偏好提高、耐心 +7 秒）。之后每七天循环。
活动同时影响真实散客的订单生成、顾客耐心和当天客流；与付费每日主推的需求权重可叠加，但不改变团体合同。没有白送金币、免费菜品或绕过库存/制作台的收入。菜单可查看活动细节，经营总览显示活动提醒，账本包含活动日历；旧存档保持兼容。
